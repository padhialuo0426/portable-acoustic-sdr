# 手把手部署运行教程

从「刚 clone 下来的仓库」开始，**一步步生成模型代码、把 C 传到开发板（树莓派等任意 Linux 板）、
编译、声学实测、取回结果、在 MATLAB 里解码**，跑出实验一的 1kHz 频谱峰值、实验二、三、四的图片还原。实验四完整操作与参数另见[实验四说明](实验四_V22bis.md)。

> 本教程以**树莓派**为例，但对任意装了 `libasound`(ALSA) 的 Linux 板（Jetson / 香橙派 / …）
> 完全一样，差别只有一个 `-d <声卡设备名>`。踩坑速查见 [Q&A](Q&A.md)。

**全程路线图**：

```
一次性准备(§1) → 传源码上板(§2) → 实验一(§3) / 实验二(§4) / 实验三(§5) / 实验四(§5A)
                                         ↑
                    改了模型？回到 §7 重新部署；嫌手敲累？§6 有图形界面
```

---

## 0. 角色与约定

| 角色 | 说明 |
|---|---|
| **[PC]** | 你的宿主机。装 **MATLAB**（负责生成模型代码、放音 `*_emit`、解码 `*_rev`/`spectrum`）。Windows 上再装 **Git Bash** 以便用 `ssh`/`scp`/`find`/`tar` 等 Linux 命令。 |
| **[板]** | 开发板。`ssh` 登进去操作。需 Linux + 麦克风 + `gcc` + `libasound`。 |

命令前缀标明在哪敲。占位符按你的实际情况替换：

- `<user>@<board-ip>` —— 板子登录账号与 IP（示例：`padhia@192.168.3.82`）
- `plughw:X,0` —— 麦克风声卡号，**用 `arecord -l` 现查**（示例：树莓派上 USB 麦克风常是 `plughw:2,0`）

> **重要原则：放音用 PC、录音用板子，不要自放自录**；而且**先在板上启动录音、再到 PC 放音**
> （`-t` 是固定录音窗口，放早了帧头会丢）。

**四个实验速查**（后面各节的具体数值都从这张表来）：

| | 实验一 | 实验二 | 实验三 | 实验四 |
|---|---|---|---|---|
| 目录 | `exp1_single_freq/` | `exp2_dpsk/` | `exp3_chirp/` | `exp4_v22bis/` |
| 模型 | `single_fre_rev.slx` | `dpsk_receive.slx` | `chirp_rev_detect.slx` | `v22_receive.slx` |
| 板上可执行 | `build/sdr_rx` | `build/dpsk_rx` | `build/chirp_rx` | `build/v22_rx` |
| 板上产出 | `single_f.mat` `single_f2.mat` | `dpsk5.mat` | `chirp5.mat` | `v22sym.mat` |
| PC 发射 | `single_fre_emit` | `dpsk_emit` | `bok_emit` | `v22_emit` |
| PC 解码 | `spectrum` | `dpsk_rev` | `bok_rev` | `v22_rev` |
| 默认图片/时长 | 单音，自己定 | `ren512b` 约 6.5s | `ren128b` 约 18.3s | `ren512b`，2400 bps 信号约 0.99s |
| 建议 `-t` | 8 | 13 | 24 | 按发射脚本或 GUI 计算，手动默认示例 7s |
| 通过标志 | 谱峰 ≈1000 Hz | BER = 0 | BER = 0 | FCS 通过且图片 BER = 0 |

实验四采样率是 **9600 Hz**，模型每次处理 960 点；不要直接套用前三个实验的 8000 Hz 设置。

## 1. 一次性准备

### 1.1 [板] 安装 ALSA 开发库（编译需要 `-lasound`，只需一次）

```bash
ssh <user>@<board-ip> 'sudo apt update && sudo apt install -y libasound2-dev'
# Fedora 系: sudo dnf install alsa-lib-devel
```

### 1.2 [PC · MATLAB] 生成板上要编译的 C 代码

> **这一步必做**，跳过的话 §2 之后板上 `make` 一定失败。

**仓库里只有 `.slx` 模型，Simulink 生成的 C 不入库**——两个版本的代码生成器产出不同，
存一份反而容易和你手里的 MATLAB 对不上。所以**用之前必须自己生成一次**。

在 MATLAB 里把**当前文件夹**切到实验目录（生成目录默认就是当前文件夹），
打开 `.slx` 按 `Ctrl+B`：

```matlab
cd <仓库根>/exp3_chirp        % 换成你要做的实验
open chirp_rev_detect.slx     % 然后 Ctrl+B，产物落在 chirp_rev_detect_ert_rtw/
```

**每个要运行的实验先生成一次**。详细参数、`slbuild` 脚本版与踩坑见各实验文档的「重新生成模型」
和 [Q10](Q&A.md)/[Q13b](Q&A.md)。

> 没生成就往下走，板上 `make` 会报 `xxx.h: No such file or directory`——
> 这不是你哪步做错了，就是这一步没做。

### 1.3 [PC]（可选但推荐）配 ssh 免密，省得每步输密码

> 这一步只为**手动流程**（§2~§5 要反复敲 `ssh`/`scp`）。
> 用图形界面 `gui.m` 的话**不需要配密钥**——它走 MATLAB 自带的 JSch，
> 填 IP + 用户名 + 密码即可，见 [§6](#6-用图形界面-guim-一键跑四个实验通用)。

```bash
ssh-keygen -t ed25519        # 一路回车（已有可跳过）
ssh-copy-id <user>@<board-ip>
```

（`ssh-keygen`/`ssh-copy-id` 在 Linux/macOS 终端与 Windows Git Bash 里都有。）

### 1.4（可选）先空跑一遍，确认工具链没问题

还没接麦克风、还没连板子时，这两件事就能做——**出问题早发现，省得后面把编译问题
误判成声学问题**：

```bash
# [PC 或板] 桩模型 + 合成音频，不需要 MATLAB 生成的代码，只验证编译与调度管线
cd exp3_chirp && make MOCK=1 && ./build/chirp_rx -t 1 && make clean && rm -f chirp5.mat
#                                        ↑ 桩模型的判决值没有意义，产物删掉免得
#                                          以后误当成真采集的数据去解
```

```matlab
% [PC · MATLAB] 拿仓库自带的真实采集样例离线解一次，验证解码链路
cd exp2_dpsk
copyfile('sample_data/dpsk5.mat', '.');  copyfile('sample_data/info_all.mat', '.');
dpsk_rev        % 应打印 BER = 0.0078（4/512），并 imshow 出还原点阵
```

样例是带信道噪声的真实录音，**BER 非 0 属正常**；能出图就说明解码这一端是好的。

## 2. 把源码传到开发板（tar over ssh，只传源码、保留目录层级）

板上要的是 **`common/` + 各实验的 `Makefile`、`src/`（手写 C）、
`<模型名>_ert_rtw/`（生成的 C）、`slprj/ert/_sharedutils/`（生成的共享工具函数，可能没有）、
`py/`（免 MATLAB 脚本）、`baseband_images/`**；`.slx` 和各 `.m` 只在 PC 上用。

> ⚠️ `<模型名>_ert_rtw/` **不在仓库里**，要先按 [§1.2](#12-pc--matlab-生成板上要编译的-c-代码)
> 在 MATLAB 里生成。没生成就打包，板上 `make` 会因为找不到模型代码而失败。

打包**按扩展名挑**（`.c/.h/.py/.bmp/Makefile`），所以 `.m`/`.slx` 自然不会被送上板，
不需要额外排除。

**[PC]** 在工程根目录执行：

```bash
find common exp1_single_freq exp2_dpsk exp3_chirp exp4_v22bis \
     -type d -name tests -prune -o \
     -type f \
     \( -name '*.c' -o -name '*.h' -o -name '*.py' -o -name '*.bmp' -o -name 'Makefile' \) \
     \( -not -path '*/slprj/*' -o -path '*/slprj/ert/_sharedutils/*' \) -print \
  | tar czf - -T - \
  | ssh <user>@<board-ip> 'mkdir -p ~/portable-acoustic-sdr && tar xzf - -C ~/portable-acoustic-sdr'
```

命令里几处刻意的选择：

- **跳过 `tests/`**：其中包含历史源码副本、录音与诊断脚本，不上传到板上。
- **保持 `common/ exp1/ exp2/ exp3/ exp4/` 同级层级**——各实验的 Makefile 用 `../common` 引用共享底层，
  层级塌了就编不过。
- **`.py` 和 `.bmp` 要上板**：§4/§5 末尾「在板上独立复现」用的就是它们。
- **`slprj/` 里只放行 `_sharedutils/`**：Simulink 的编译缓存不必上板，但**共享工具函数是生成代码
  的一部分**（`Makefile` 会自动把它编进去）。目前若未产出这个目录，`find` 匹配不到就跳过，
  不影响；一旦哪次改模型引入了它，这条命令不用改也能正确带上。
- **用 tar over ssh 而不是 rsync**：`rsync` 默认**不在 Windows 的 Git Bash 里**（需手动加装），
  而 `find`/`tar`/`ssh` 都是 Git Bash 自带；这条命令在 Linux/macOS/Windows 三种宿主上**完全一致**。

传完后板上应是（只有源码，干净）：

```
~/portable-acoustic-sdr/
├── common/{include/*.h, src/*.c}
├── exp1_single_freq/{Makefile, src/*.c,*.h, single_fre_rev_ert_rtw/*.c,*.h}
├── exp2_dpsk/{Makefile, src/*.c,*.h, dpsk_receive_ert_rtw/*.c,*.h, py/*.py,
│              baseband_images/*.bmp}
├── exp3_chirp/{Makefile, src/*.c,*.h, chirp_rev_detect_ert_rtw/*.c,*.h, py/*.py,
│              baseband_images/*.bmp}
└── exp4_v22bis/{Makefile, src/*.c,*.h, v22_receive_ert_rtw/*.c,*.h, baseband_images/*.bmp}
```

> 以后改了算法、在 PC 上重新生成模型，**再跑一次这条命令**即可——但有个前提，见 [§7](#7-改了模型之后如何重新部署)。

## 3. 实验一 · 单频信号

PC 扬声器放一个 1kHz 单音，板子录下来滤波存盘，PC 端 FFT 看谱峰落在哪。
**目的是打通整条最小链路**，没有解码、没有 BER。

### 3.1 [板] 编译 + 确认麦克风声卡号

```bash
ssh <user>@<board-ip>
cd ~/portable-acoustic-sdr/exp1_single_freq
make clean && make            # 换平台必须先 clean，否则旧 .o 时间戳会误判已最新
arecord -l                    # 看麦克风是 card 几，记下 X
```

### 3.2 声学实测（先录后放）

**[板]** 先启动采集（阻塞约 8 秒，给你切到 MATLAB 的时间）：

```bash
./build/sdr_rx -d plughw:X,0 -t 8       # X 按 arecord -l 实际改
```

**[PC · MATLAB]** 看到板子开始录后，**立刻**运行发射脚本播 1kHz 单音：

```matlab
cd exp1_single_freq
single_fre_emit
```

### 3.3 [PC] 取回 .mat + 看频谱

```bash
scp <user>@<board-ip>:~/portable-acoustic-sdr/exp1_single_freq/single_f.mat exp1_single_freq/
```

**[PC · MATLAB]**（`spectrum.m` 就在 `exp1_single_freq/` 下，`cd` 进去即可）：

```matlab
cd exp1_single_freq
spectrum('single_f.mat','toFileData')
```

✅ **频谱峰值落在约 1000 Hz** → 实验一通过。

谱峰偏得离谱、或者波形一片平：先看 [Q4](Q&A.md)（麦克风没接好）和 [Q7](Q&A.md)（声音没从扬声器出去）。

## 4. 实验二 · DPSK 差分相移键控

把一张 1-bit 图片当基带信息发出去，板上逐码元出判决值，PC 端帧同步、算 BER、还原点阵。

### 4.1 [板] 编译

```bash
ssh <user>@<board-ip>
cd ~/portable-acoustic-sdr/exp2_dpsk
make clean && make
arecord -l                    # 确认声卡号 X
```

### 4.2 [PC · MATLAB] 选定图片（发射端与解码端必须一致）

分别打开 `exp2_dpsk/dpsk_emit.m` 和 `dpsk_rev.m`，把顶部 `img_name` 改成同一张
（默认 `ren512b.bmp`，约 6.5s）。**两边不一致的话解码会报「未找到帧头/帧尾」**——
帧间距是按图片比特数算的。

### 4.3 声学实测（先录后放）

**[板]** 先启动采集（`ren512b` 约 6.5s，给到 `-t 13` 留余量）：

```bash
./build/dpsk_rx -d plughw:X,0 -t 13
```

**[PC · MATLAB]** 立刻运行发射脚本（它会显示发送图、用 `sound()` 播放，并把 `info_all.mat` 写到实验目录）：

```matlab
cd exp2_dpsk
dpsk_emit
```

换大图时 `-t` 按 `dpsk_emit` 打印的建议值给（`lzu2048b` 要到 28 秒左右），见 [Q6](Q&A.md)。

### 4.4 [PC] 取回判决数据 + 解码算 BER

```bash
scp <user>@<board-ip>:~/portable-acoustic-sdr/exp2_dpsk/dpsk5.mat exp2_dpsk/
```

**[PC · MATLAB]**（`dpsk5.mat` 与 `info_all.mat` 都在 `exp2_dpsk/`，`dpsk_rev` 自动读）：

```matlab
cd exp2_dpsk
dpsk_rev
```

✅ **命令窗口 `BER = 0`、`imshow` 还原出正确点阵** → 实验二通过。

### 4.5 在板上独立复现（不需要 MATLAB）

板子只要有 python3，整个实验可以在板上闭环跑完。以下命令**全部在板上**、
`cd` 到 `~/portable-acoustic-sdr/exp2_dpsk`：

```bash
IMG=baseband_images/ren512b.bmp           # 换任意图片；缺省即此张

python3 py/dpsk_emit.py $IMG              # 生成发射信号 + 打印建议 -t

# A) 文件直喂（无声学噪声，纯测 DSP/解码，应得 BER=0）
make AUDIO=file && ./build/dpsk_rx -d dpsk_tx.raw

# B) 真实声学（-t 用上一步打印的建议值）
make && (aplay -q dpsk_tx.wav &) ; ./build/dpsk_rx -d plughw:X,0 -t 13

python3 py/dpsk_rev.py $IMG               # 帧同步 + BER + ASCII 还原图像
```

> A) 这条**不碰声卡**，是排错时最有用的一步：它 BER=0 就说明模型代码、编译、解码都没问题，
> 剩下的一定是声学/采集侧的事。见 [Q15](Q&A.md)。
>
> B) 这条是**板子自放自录**，和 §0「放音用 PC、录音用板子」的原则相反——没有 MATLAB 时
> 只能如此。板子的扬声器和麦克风挨得近、容易过载，解不出先按 [Q5](Q&A.md) 压低音量；
> 手边有 PC 的话，正路仍是 §4.3。

## 5. 实验三 · chirp 扩频

结构与实验二完全相同，只是调制换成上扫/下扫 chirp，符号率低得多（10 符号/秒），
所以信号更长、抗噪更好。

### 5.1 [板] 编译

```bash
ssh <user>@<board-ip>
cd ~/portable-acoustic-sdr/exp3_chirp
make clean && make
arecord -l                    # 确认声卡号 X
```

### 5.2 [PC · MATLAB] 选定图片（发射端与解码端必须一致）

分别打开 `exp3_chirp/bok_emit.m` 和 `bok_rev.m`，把顶部 `img_name` 改成同一张
（默认 `ren128b.bmp`，最短约 18.3s，先用它跑通）。

### 5.3 声学实测（先录后放）

**[板]** 先启动采集（`ren128b` 约 18.3s，给到 `-t 24` 留余量）：

```bash
./build/chirp_rx -d plughw:X,0 -t 24
```

**[PC · MATLAB]** 立刻运行发射脚本：

```matlab
cd exp3_chirp
bok_emit
```

> ⚠️ **换大图一定要重算 `-t`**：本实验每符号 0.1s，`lzu2048b`（2048 位）要放 **210 秒**、
> `-t` 得给到 **217**。照抄上面的 24 必然解不出。`bok_emit` 会把建议值打印出来，照着给。

### 5.4 [PC] 取回判决数据 + 解码算 BER

```bash
scp <user>@<board-ip>:~/portable-acoustic-sdr/exp3_chirp/chirp5.mat exp3_chirp/
```

**[PC · MATLAB]**（`chirp5.mat` 与 `info_all.mat` 都在 `exp3_chirp/`，`bok_rev` 自动读）：

```matlab
cd exp3_chirp
bok_rev
```

✅ **命令窗口 `BER = 0`、`imshow` 还原出正确点阵** → 实验三通过。

### 5.5 在板上独立复现（不需要 MATLAB）

与 [§4.5](#45-在板上独立复现不需要-matlab) 同构，脚本换成 `py/bok_emit.py` / `py/bok_rev.py`，
产物换成 `chirp_tx.raw/.wav` 与 `chirp5.mat`：

```bash
IMG=baseband_images/ren128b.bmp           # 缺省即此张（最短 18.3s）

python3 py/bok_emit.py $IMG               # 生成发射信号 + 打印建议 -t
make AUDIO=file && ./build/chirp_rx -d chirp_tx.raw          # A) 文件直喂
make && (aplay -q chirp_tx.wav &) ; ./build/chirp_rx -d plughw:X,0 -t 24   # B) 声学
python3 py/bok_rev.py $IMG                # 帧同步 + BER + ASCII 还原图像
```

## 5A. 实验四 · V.22bis 风格图片传输

实验四使用 600 波特、2400 bps 的 16-QAM 或 1200 bps 的 QPSK。板上输出的是复符号，电脑继续做判决、解扰和 HDLC/FCS 校验，具体设置见[实验四说明](实验四_V22bis.md)。

```matlab
cd <仓库根>/exp4_v22bis
setup_paths
slbuild('v22_receive')
gui
```

生成代码后，在 GUI 中自检、同步源码并编译、校准电平，然后收发。手动流程使用板上 `./build/v22_rx -d plughw:X,0 -t 7`，电脑运行 `v22_emit`；取回 `v22sym.mat` 后运行 `v22_rev`。实际窗口按所选图片和速率计算。

实验四已实测 PC 耳机输出到 USB 声卡输入的有线链路，空气传播性能尚未验收。本机离线调试文件集中在 `exp4_v22bis/tests/`，不入库，日常收发不依赖它；本机保留测试脚本时可运行 `addpath('tests'); v22_run_tests`。

## 6. 用图形界面 `gui.m` 一键跑（四个实验通用）

> **首次学习请先按 §3~§5 手动走一遍**。那些命令本身就是要学的 Linux 过程，
> 界面只是理解之后的提速工具（见 [Q9](Q&A.md)）。

四个实验各有一个 `gui.m`，用法完全一致：

```matlab
cd exp2_dpsk        % 或 exp1_single_freq / exp3_chirp / exp4_v22bis
gui
```

按 **① 自检 → ② 同步源码到板上并编译 → ③ 电平校准 → ④ 一键声学实测** 的顺序点。
这四步覆盖了 §2 传代码、§4.1 编译、§4.3 实测、§4.4 取回解码的**全部**动作——
**手动流程里唯一不能被它替代的是 [§1.2](#12-pc--matlab-生成板上要编译的-c-代码) 的代码生成**，
那步必须你自己在 MATLAB 里做。

### 连接方式

**只需填「IP 地址」「用户名」「密码」三项**，和 MathWorks 树莓派支持包一样——
界面不调用系统的 `ssh`/`scp`，而是用 MATLAB **基础安装**自带的 JSch
（`matlabroot/java/jarext/jsch.jar`，不属于任何支持包），所以
**Windows / macOS / Linux 行为完全一致，不需要配密钥、不需要装任何额外工具**。

> 「IP 地址」填板子的局域网 IP（如 `192.168.3.82`），板上 `hostname -I` 可查。
>
> MATLAB 带的 JSch 是 0.1.x，不支持 ed25519 私钥，所以界面只做**密码认证**。
> 手动流程（§2~§5）用的是系统 ssh，不受此限制。

### 四个按钮各做什么

**① 自检** —— 连上板子、跑 `arecord -l` 现场枚举采集设备填进下拉框，并报告板上源码与
可执行的现状。所以「板上路径」和「ALSA 设备」两项**打开界面时是空的、灰的**，自检成功后
才自动填好并变为可改（显示的一切都是刚刚验证过的，不是本地推算的）。ALSA 设备下拉里是
`plughw:2,0 — KSS K10 (USB Audio)` 这样的完整名称，换麦克风或重插 USB 后点旁边的 ⟳ 重新枚举。

**② 同步源码到板上并编译** —— 一次做完 §2 的传代码和 §3.1/§4.1/§5.1 的 `make`：把 `Makefile`/`.c`/`.h`/
`.py`/`.bmp` 打包送过去（等价于 §2 那条 tar over ssh，但用 MATLAB 自带的 tar，**Windows 上
不需要 Git Bash**），再触发板上 `make clean && make`——**编译仍在板子上、用板子自己的 gcc**。
失败时会把 gcc 的最后几行报错打到日志里。

**③ 电平校准** —— 板上录 6 秒、本机同时放 4 秒测试音，回收后报 RMS 与峰值，并判定
"太弱 / 偏低 / 合适 / 偏高"。**这是定位「板上采到全 0」类问题最快的手段**，见 [Q4](Q&A.md)/[Q7](Q&A.md)。

**④ 一键声学实测** —— 依次：板上启动采集 → 本机扬声器放音 → 等采集窗口跑完 → 取回 `.mat` →
解码/分析 → 显示结果（实验一是频谱图与谱峰，实验二/三是 BER 与并排的发送/还原点阵）。
采集窗口 `-t` 按所选图片自动算，不用自己数。

### 两个要留意的点

**时序不用紧张** —— 板上程序从启动到真正采集的死区实测只有 70~175ms，而帧同步是在整条判决流里
扫 m 序列、不要求对齐；实验一的 FFT 更是对整段录音做的。只要信号完整落在采集窗口内就能解，
默认 1s 前导 + 2s 尾部余量足够。

**「输出设备」这一项** —— 宿主机接着蓝牙耳机时，系统默认输出会被耳机抢走，声音根本没从扬声器
发出去，板上会采到一片 0。界面默认优先选内置扬声器、显式指定设备 ID，选到耳机时还会告警——
但**手动跑 `*_emit.m` 时没有这层保护**，见 [Q7](Q&A.md)。

## 7. 改了模型之后如何重新部署

改了 Simulink 模型、在 PC 上重新生成了 C 代码（步骤见
[实验一](实验一_单频信号.md)/[实验二](实验二_DPSK.md)/[实验三](实验三_chirp扩频.md)/[实验四](实验四_V22bis.md)的模型生成说明），
按下面重新部署。

### 7.1 [PC] 若生成的 `.c` 改了名或减少了，先删板上的生成目录

`tar` 解包**只覆盖/新增、不删除**。如果这次重新生成让某个 `.c` 改了名或消失，
板上残留的「孤儿 `.c`」会被 Makefile 的 `*.c` 通配编进去而报错。
拿不准就删一次，反正马上会重传：

```bash
# 生成代码独占 *_ert_rtw/，通配删掉即可，不必关心模型叫什么
ssh <user>@<board-ip> 'rm -rf ~/portable-acoustic-sdr/exp3_chirp/*_ert_rtw'
```

### 7.2 [PC] 重传代码

**把 [§2](#2-把源码传到开发板tar-over-ssh只传源码保留目录层级) 那条 `find | tar | ssh` 原样再跑一次**，
改过的 `.c/.h` 会被盖成最新。

### 7.3 [板] 清干净重新编译（**务必 `make clean`**）

```bash
ssh <user>@<board-ip>
cd ~/portable-acoustic-sdr/exp3_chirp     # 或 exp1_single_freq / exp2_dpsk
make clean && make
```

**`make clean` 不能省**：PC 与板子时钟可能有偏差，若新 `.c` 的时间戳不比旧 `.o` 新，
`make` 会误判"已是最新"而不重编，跑的还是旧逻辑。

### 7.4 接口改了名时同步胶水层

如果重新生成时改了 **Inport/Outport 的名字**，只需改 `src/model_glue.c` 这**一处**
对应的字段名——它也在 §7.2 传输的 `.c` 里，**在 PC 上改好再重传**即可。

### 7.5 照常运行

回到 [§3](#3-实验一--单频信号)/[§4](#4-实验二--dpsk-差分相移键控)/[§5](#5-实验三--chirp-扩频) 的「声学实测」重新跑一遍验证。

### 7.6 用图形界面的话：7.1~7.3 就是点一次「②」

界面的「② 同步源码到板上并编译」**每次同步前都会先 `rm -rf` 板上的 `*_ert_rtw`**，
所以 §7.1 那个孤儿 `.c` 的坑根本不会出现——不需要你去判断这次生成有没有改文件名；
编译又走 `make clean && make`，§7.3 的时间戳问题也一并避免。

手写的 `src/*.c`、`py/`、`../common/` 只覆盖、不删除——那里的文件不会因为重新生成模型而改名。
§7.4 的情况同样是在 PC 上改好、点这个按钮即可。

## 8. 跑不通时

先分层隔离，**别一上来就怀疑声学**——按 [Q15](Q&A.md) 的顺序：
**文件直喂**（§4.5 的 A 条）→ **录音喂文件** → 才轮到实采路径。

按「现象 → 原因 → 解决」整理在 [Q&A](Q&A.md)，最常见的几条：

| 现象 | 多半是 |
|---|---|
| `make` 报找不到 `xxx.h`（模型名那个） | §1.2 的代码生成没做 |
| `make` 报找不到 `asoundlib.h` / `-lasound` | 板上没装 `libasound2-dev`（[Q8](Q&A.md)） |
| `capture slave is not defined` / 打不开 `default` | 没带 `-d`，用 `-d plughw:X,0`（[Q1](Q&A.md)/[Q2](Q&A.md)） |
| USB 重插/重启后打不开设备 | card 号变了，跑之前 `arecord -l` 现查（[Q2](Q&A.md)） |
| 录到静音（RMS 个位数） | 麦克风没接好，非软件问题（[Q4](Q&A.md)） |
| 判决流/录音全 0 | 宿主机接了蓝牙耳机，声音没从扬声器出去（[Q7](Q&A.md)） |
| 判决恒 −1 / 帧同步失败 | 声道问题，接收端已默认单声道 `-c 1`（[Q3](Q&A.md)） |
| 大图解不出、小图正常 | `-t` 不够，按 `*_emit` 打印的时长加足（[Q6](Q&A.md)） |
| 解码报「未找到帧头/帧尾」 | 发射端与解码端 `img_name` 不一致，或上一条 |
| 重新生成代码报 `Toolchain ... is not registered` | [Q10](Q&A.md) |
| 生成的代码里没有 `ExtU`/`ExtY`，`model_glue.c` 编不过 | R2022a 没设 `RootIOFormat`（[Q13b](Q&A.md)） |
