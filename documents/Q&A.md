# 常见问题 Q&A

按症状定位，再做有针对性的检查。首次操作或重新部署时，按[构建与部署](构建与部署.md)中的步骤执行。

| 症状 | 跳转 |
|---|---|

| 编译失败、找不到头文件或 `clean` 目标 | [Q6](#编译失败) |
| 信号很弱、全零、削顶或路由不明 | [Q3](#电平与路由) |
| 找不到帧、大图失败 | [Q5](#帧同步) |

## 一、采集与播放

<a id="采集设备"></a>
### Q1. `capture slave is not defined`、`Invalid argument` 或打不开设备

先看构建日志是否为 `AUDIO=alsa`。若是 `AUDIO=file`，`-d plughw:2,0` 会被当成文件名，出现 `audio_io_file: 打不开 ...`；按[构建模式](构建与部署.md#构建模式)重编真实采集程序。

使用 ALSA 时，在板上执行 `arecord -l`，把 `-d` 改为实际设备，例如 `plughw:2,0`。未传 `-d` 时使用 `default`，而系统的默认 PCM 可能只配置了播放，没有采集通路。

USB 重插和重启可能改变 card 号，应重新枚举。`plughw` 可以转换采样率和声道格式，直接用 `hw` 时则要求硬件支持请求格式；实验四尤其要注意 9600 Hz。播放设备看 `aplay -l`，不能用播放列表替代采集列表。

<a id="声道"></a>
### Q2. `-c 2` 是否表示只用左声道？

不是，它表示采集两个声道。实验一至三把两路交给模型相加；实验四在运行时求左右平均。默认 `-c 1` 采集单声道，具体幅度规则见[命令行参考](接口与参数参考.md#命令行)。

若判决恒定或幅度异常，检查左右路是否有信号、是否反相相消，再比较单声道模式。恒定判决还可能由信号缺失、不同步或采集截断导致，不能仅凭这个症状断定是声道问题。

<a id="电平与路由"></a>
### Q3. RMS 很小、输出全零，或者峰值接近 32767

1. 确认 PC 真正使用的输出设备，以及它对应的系统音量、静音状态。手动 `sound()` 使用默认设备，GUI 使用界面所选设备，两者可能不同。
2. 确认板上选择的输入设备、实际接口和采集增益。线路输入与麦克风输入的适用电平不同；接错孔、输入静音和错误路由都可能造成低电平。
3. 用 GUI“电平校准”测量，再检查录音波形。提高或降低增益时只改一处，观察信号是否连续、是否出现平顶或明显谐波。
4. 若停音后有长拖尾，确认声卡的混响、回声、变声等效果已关闭。实体旋钮不一定显示在 ALSA 控件中。

RMS 没有适用于所有声卡的固定通过值。接近满幅可能削顶，幅度很低也可能是路由或软件配置问题；需要结合波形、噪声底和接收结果判断。

需要查看硬件混音器时，在板上运行 `amixer -c CARD_NUMBER scontrols`，将 `CARD_NUMBER` 替换为 `arecord -l` 中的卡号，再按实际控件调整；不要假设所有设备都有同名录音增益控件。

虚拟机可走虚拟声卡输出，也可走远程音频。检查最终声音是否到达接线的物理接口，再做电平测量，不能根据“QEMU”或“远程音频”名称直接判定通路好坏。

若低采样率播放时信号完整却不稳定，可以把**播放副本**重采样到输出设备常用的 48 kHz，保持接收模型采样率不变，比较同一波形的结果。不要只修改 `sound` 或 `audioplayer` 的采样率参数，否则会改变信号的时长和载波频率。

在 PC / MATLAB 中先准备已生成的发送 WAV：

```matlab
[x, fs] = audioread('YOUR_TX_WAV');
[p, q] = rat(48000 / fs);
y = resample(x, p, q);
player = audioplayer(0.1 * y, 48000);
```

`YOUR_TX_WAV` 替换为发送 WAV 路径，例如 MATLAB 发射脚本 `v22_emit` 生成的 `v22_tx.wav`。0.1 是起始试验幅度，仍需校准实际电平。板上采集启动后，再执行 `playblocking(player)`；它使用系统默认输出。一次改善只能说明这种播放配置在该轮有效，还需重复确认，不能单凭它确定根因。


<a id="丢样"></a>
### Q4. 日志有 overrun，或录音出现突发截短、断点

保存出错日志与原始录音，检查 USB 连接、供电、系统负载和音频设备是否被其他程序占用。可在保持 3.5 mm 接线不变的情况下换一个 USB 口，再比较相同参数下的结果。

overrun 表示采集缓冲区未被及时读取，信号缺口会破坏滤波器和同步状态。即使系统恢复继续采集，也不能把缺失样本当作完好数据；先定位丢样，再评价算法。

<a id="帧同步"></a>
### Q5. 小图正常，大图失败；或者找不到帧头/帧尾

1. 核对完整波形时长和 `-t`。实验三默认图为 18.3 秒，大图可超过 210 秒；先采集再播放，并包含操作等待与尾部余量。
2. 实验二、三核对发射和解码使用的图片尺寸，以及 MATLAB 的 `info_all.mat` 是否来自本轮发送。尺寸影响两段 m 序列的预期间距；同尺寸但内容不同主要影响 BER 对照。
3. 实验四核对发送、板上 `-b`、解码 `RATE` 三处速率。它使用 HDLC 标志和 FCS，不使用实验二、三的 m 序列同步方式。
4. 检查电平、丢样和同步捕获。采集时长足够仍失败时，按[分层排查](#分层排查)回放同一输入。

GUI 的“前导余量”是采集提前等待，调制前导已在完整信号中；增加等待不能替代修复错误的帧结构或速率配置。

## 二、构建与 MATLAB

<a id="编译失败"></a>
### Q6. 板上编译失败，如何按报错定位？

| 报错 | 先检查 | 处理 |
|---|---|---|
| `asoundlib.h` 或 `-lasound` 找不到 | ALSA 开发库 | 安装发行版对应开发包，Debian 系为 `libasound2-dev` |
| `<模型名>.h: No such file or directory` | 是否已生成并上传真实模型 C | 按[生成模型代码](构建与部署.md#生成模型代码)生成，再确认包内有生成头文件 |
| `No rule to make target 'clean'` | 远端工作目录和实际 Makefile | 确认运行在所选实验目录，重新同步仓库 Makefile；核对文件未被编码转换损坏 |
| 模型函数重复定义、引用旧符号 | 上一轮遗留的生成 `.c` | 按[重新部署](构建与部署.md#重新部署)替换整个生成目录并清理重编 |
| 找不到 `_U/_Y` 或 `ExtU/ExtY` | 根 I/O 生成方式、端口名与胶水层 | 恢复结构体根 I/O，核对接口并重新生成 |

GUI 的“同步编译”不负责生成模型 C；点击按钮前先在 PC 完成生成。编译成功也应确认末行的 `MODEL` 和 `AUDIO`，避免运行了不符合用途的后端。

<a id="代码生成"></a>
### Q7. `Toolchain 'GNU GCC Embedded Linux' is not registered`，或出现编译器警告

旧配置可能保留了板卡支持包注册的工具链。按[公共代码生成配置](构建与部署.md#生成模型代码)设为 `Automatically locate an installed toolchain`，同时保持 `GenCodeOnly=on`。

代码只在 PC 生成、在板上 gcc 编译时，不要求 PC 安装 C 编译器。`Unable to detect supported compiler` 这一类提示应结合本次生成结果判断：只有生成成功、需要的 C 和头文件齐全时，才能继续部署；不能据此忽略其他诊断。

本工程用 Outport 输出、板级 `mat_sink.c` 写 MAT，因此 `MatFileLogging` 保持关闭。不要用生成代码中的 `To File` 或日志运行时替换这条路径，否则可能重新引入板上没有的依赖，或使未使用的输出被优化掉。

<a id="模型版本"></a>
### Q8. 模型能打开，是否意味着旧版 MATLAB 也能生成代码？

不能。模型保存格式、工具箱对象和代码生成接口是不同层面的兼容性，当前边界见[软件与版本](接口与参数参考.md#软件与版本)。实验一至三的接收模型保留 R2022a 文件格式，但不能据此宣称实际 R2022a 生成已验证。

需要向旧版本导出时，先保存副本，再用 Simulink 的“导出到先前版本”功能选择目标版本。验证能打开、能生成接口匹配的 C，并完成同一输入的解码对照后，再替换仓库模型。新增发送模型及实验四、五接收模型不能直接假设可导出到 R2022a。

`DesignFlags`、滤波器设计对象等跨版本提示应结合生成与回放结果处理。脚本中文乱码时检查文件是否按 UTF-8 打开和保存，不要为消除显示乱码随意重编码模型生成文件。

## 三、定位接收问题

<a id="分层排查"></a>
### Q9. 如何区分数字算法、音频信号和实时采集问题？

按同一图片、同一速率逐层比较：

1. **干净 PCM 回放**：按[文件回放](构建与部署.md#文件回放)运行真实模型。BER=0 说明这个输入通过了当前数字链路，不代表所有信道条件下都正确。
2. **录音回放同一模型**：将实际音频保存成规定格式，再由 file 后端处理，观察是否重现错误。
3. **比较实时与回放结果**：核对声道合并、采样率、帧边界和捕获余量，再查 ALSA 调度、丢样与负载。
4. **实验四独立 WAV 解码**：按[直接解 WAV](构建与部署.md#直接解-wav)交叉检查。离线解码器与模型的定时、AGC 不同，一端成功只能缩小范围，不能单独证明另一端存在程序错误。

录音回放示例：**板上 / 实验四目录**，设备号按实际替换，采集期间从 PC 播放一次对应信号。

```bash
SDR_RUN=$(mktemp -d)
arecord -D plughw:2,0 -t raw -f S16_LE -r 9600 -c 1 -d 7 "$SDR_RUN/input.raw"
```

录音成功后，在同一个终端、同一个实验目录中回放：

```bash
make MODEL=real AUDIO=file BUILD="$SDR_RUN/build" && \
  (cd "$SDR_RUN" && ./build/v22_rx -b 2400 -d input.raw) && \
  echo "$SDR_RUN"
```

输入是无 WAV 头的单声道 S16_LE；实验一至三采样率改为 8000 Hz，并使用对应可执行文件。结果落在打印的临时目录中，需要保留时另存。接收程序的 `-r raw.mat` 写的是 MAT 容器，不能把它改名为 `.raw` 后直接输入。

<a id="星座与ber"></a>
### Q10. 实验四 BER=0，为什么星座图仍可能散乱？

先确认显示范围。全部符号包含前导捕获、静音和异常过程，不能直接代表有效图片帧；GUI 默认“m序列测量窗口”更适合检查数据段，也可单独选择“有效图片帧”。

实验 BER 比较 m 序列定位窗口中的图片比特与参考图，星座反映判决前的实际符号质量。只要点没有越过判决边界，图片可能无误，但噪声、增益波动和残余相位仍会使点簇变宽。评估稳定性时同时记录失败发送，不能只挑成功帧的 BER。

GUI 让坐标轴原点居中、I/Q 等尺度，并保留实际数据。解码失败应清空旧结果，不能显示上一轮图片作为本轮结果。详见[实验四结果说明](实验四_V22bis.md#解码与星座图分别说明什么)。

<a id="qpsk旋转"></a>
### Q11. QPSK 星座出现固定旋转怎么办？

先核对 `-b 1200`、发射与解码的 `RATE=1200`。QPSK 应使用单位圆对角线参考，不能使用 16-QAM 的四个象限内点；后者可能把 QPSK 锁到偏离对角线约 26.6° 的位置，图片仍可能因象限判决未变而 BER=0。

若使用了旧生成代码，按[重新部署](构建与部署.md#重新部署)生成、同步并编译，重新打开 GUI 后采集。旧 `v22sym.mat` 不会因更新模型而自动校正；可以用保留的原始音频回放新版接收机。

任意旋转或随时间转动还可能来自残余频偏、低信噪比或捕获不足，应结合全部符号随时间的变化判断，不能把所有旋转都归结为同一问题。

<a id="接收滤波"></a>
### Q12. 接收端还需要增加滤波器吗？

实验四下变频后已有 129 抽头 RRC 匹配滤波。先确定干扰频带，再判断是否需要额外带通；带内混响、削顶和丢样不靠带通解决。额外滤波还会引入时延和频响变化，需要重新验证捕获与帧尾余量。

WAV 突发定位中的带通只用于检测能量，并不替换实际送入解调器的波形。现有接收链见[实验四模型](实验四_V22bis.md#板上接收链从采样点到复符号)。

<a id="解帧诊断"></a>
### Q13. 实验四要么 BER=0，要么未解出帧，如何区分原因？

先看“m 序列定位”和“接收状态”。实验 BER 已与 FCS 分开：只要首尾 m 序列相关、间距符合要求且窗口唯一，就按本次参考图片的位填充位置计算 BER。少量误码可能让 HDLC/FCS 失败，但不必同时失去 BER；两端都要选择相同的图片。

| 结果 | 能说明什么 |
|---|---|
| 帧标志不足 | 无法确定完整边界；可能是标志误码、录音不完整或解调异常 |
| 有标志，但过短、位填充非法或长度异常 | 候选区间未形成可校验帧；不能仅凭有标志认定同步正确 |
| 有候选帧，FCS 全部失败 | 已进入校验阶段；可能有数据误码，也可能误识别边界 |
| FCS 通过，但图片格式无效 | 校验后的载荷无法按实验四图片格式还原 |
| 实验 BER 非零、FCS 失败 | m 序列定位后的图片比特有误；显示本次实验对照点阵，但不视为有效图片帧 |
| 实验 BER 为零、FCS 失败 | 图片比特一致仍不足以接收，例如 FCS 字节可能损坏 |

m 序列无法可靠定位时不能给出实验 BER，也不应把失败换算成 100% 误码。重复发送时结合每次的 m 序列定位、实验 BER 和 FCS 结果判断。标记阈值、参考位置映射和 BER 计算范围见[实验四结果说明](实验四_V22bis.md#解码与星座图分别说明什么)。

<a id="sstv接收"></a>
### Q14. 实验五未找到 VIS、出现斜图或缺行怎么办？

先确认发送模式在支持的 20 种模式中、模型与采集率为 48000 Hz，并按 GUI 显示的时长完整采集。Martin M1 完整音频约 115.3 秒，GUI 默认采集 119 秒；其他模式自动调整采集窗口。手动操作需留出切换余量，并在接收启动后立即播放。没有 VIS 时无法确定模式和首行，接收图会保持空白。

斜图通常需要检查收发时钟差异，突然错行则应检查采集丢样、音频重定向卡顿或同步脉冲失真。当前接收端逐行定位并估计时钟偏差，但不会补造缺失内容；无同步或不完整的行显示灰色。检查实际接线、电平、音效和采集日志，再判断算法是否需要调整。

“VIS 偶校验通过”只说明模式编号通过检查。SSTV 没有图像 FCS；二值像素误差率和 PSNR 只比较完整接收的行，应同时看完整行数。指标含义见[实验五结果说明](实验五_SSTV.md#如何理解结果)。
